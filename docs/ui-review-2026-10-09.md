### 1-2. 新商品の売上が、対象 0 件なのに「0円」と出る（高）

`/api/sales/new-products`（`sales.new_product_summary`）は、売上計上の案件が 0 件でも `totals: {"全額": 0.0, "増分": 0.0}` を返す。`viewSales` の「新商品」カードはそれを `yen()` に通すので **「全額で数える分 0円」** と表示される（本番の現在値がこの状態: `count 0` / `counted 0`）。

0円は「売れなかった」という主張になる（N-10）。正しくは「対象なし（売上計上の案件が 0 件）」。

```js
// before（viewSales の新商品カード）
el("td", { "class": "np-num", text: yen(n.totals["全額"]) })
// after
el("td", { "class": "np-num", text: n.counted ? yen(n.totals["全額"]) : "対象なし（売上計上の案件 0 件）" })
```

サーバー側も `counted == 0` のときは `totals` の金額を `null` にするのが筋（画面の直しだけだと、月次レポートや HUB で同じ 0 が出る）。

もう1点。**「新商品の売上」は2つの定義が併存している**:
- `past_product`（「新商品売上状況」の表・発売から12か月以内の全新商品・2023-04〜2026-03 の36か月）。HUB の `revenue_newproduct` はこちら（`hubmetrics.build`）
- アプリの案件のうち「売上計上」を立てたもの（`new_product_summary`）

ダッシュボードに出すときは**どちらかを名指しで**出す。並べるなら別のグラフにする。

### 1-3. タスクの月次負荷: 時間が空の行を 0h として足している（高）

`task.load_by_month_role` の SQL が `SUM(COALESCE(t.hours,0))`（`work_item` も同じ）。時間の入っていない行が**0時間として合計に入り、件数 `n` には数えられる**。本番の写しでは:

- 案件外の仕事 2026-06・07・08 は**全行の時間が空**（1行・6行・5行）→ 画面では「0h」
- 案件タスク 2026-10 は 62行のうち 16行が空、2027-04 は 1行すべて空 → 「0.0h」

このまま積み上げ棒にすると「6〜8月は負荷ゼロ」と描かれる。**グラフにする前に API に「時間未入力の件数」を足す**。

```python
# before（load_by_month_role の2本の SQL）
"SUM(COALESCE(t.hours,0)) AS h, COUNT(*) AS n, "
# after（足すだけ。h の意味は変えない）
"SUM(COALESCE(t.hours,0)) AS h, COUNT(*) AS n, SUM(t.hours IS NULL) AS hu, "
# 行にも足す
row["hours_unknown_n"] = row.get("hours_unknown_n", 0) + int(r["hu"] or 0)
```

画面では各月に「時間未入力 n 件（合計に入っていません）」を**棒の下に語で**出す。全行が未入力の月は棒を描かず「未計測」と描く（§3-2）。

**金額の書式を1つにする。**`function yen` が IIFE の同じ階層に2つある（アイデアの所の「未入力／¥」版と、売上の所の「未計測／円」版）。**後に書いた方が全体に効く**ので、前の版は使われていない。結果:
- アイデアの「想定粗利額」が空のとき「未入力」ではなく「未計測」と出る（入れていないだけなのに、測れないと読める）
- 残っている版は `""` を空とみなさず、`Math.round("")` = 0 で「0円」になる

```js
// before（2つある）
function yen(v) { return (v === null || v === undefined || v === "") ? "未入力" : "¥" + Number(v).toLocaleString("ja-JP"); }
function yen(v) { return (v === null || v === undefined) ? "未計測" : Math.round(v).toLocaleString("ja-JP") + "円"; }
// after（1つにする。欠けたときの語は呼ぶ側が選ぶ）
function yen(v, missing) {
  return (v === null || v === undefined || v === "") ? (missing || "未計測") : Math.round(v).toLocaleString("ja-JP") + "円";
}
// アイデアの入力欄由来の値
yen(x.expected_margin_yen, "未入力")
```

「円」で統一する（月次レポート・売上画面・原価が「円」なので。チームの共通ルール表は `¥0` と書いているが、アプリの中でそろっていることを優先する）。グラフの目盛りだけ「万円」に縮めてよい（`fmtShort`）。表は縮めない。

// after: 幅が変わったとき・たたみを開いたときに描く。幅 0（たたまれている）のあいだは描かない
function svgHost(draw, minH) {
  var host = el("div", { "class": "np-chart-svg" });
  if (minH) host.style.minHeight = minH + "px";
  var lastW = 0;
  function redraw(w) {
    w = Math.floor(w || 0);
    if (w < 1 || Math.abs(w - lastW) < 8) return;
    lastW = w;
    host.textContent = "";
    host.appendChild(draw(w));
  }
  if (window.ResizeObserver) new ResizeObserver(function (es) { redraw(es[0].contentRect.width); }).observe(host);
  else requestAnimationFrame(function () { redraw(host.clientWidth || 600); });
  return host;
}

| やらないこと | なぜ |

## 5. ダッシュボード（`viewHome`）— 優先度 高

### 5-1. いま見づらい所

1. **1-4 の「自分」の食い違い**（23件と0件）と、発売済2件の G0 判定待ち
2. 上から「自分のやること」（表が最大12行）→「いま詰まっているもの」（3枚）→「月次で見るもの」（3枚）→「直近の発売予定」→「要注意」の表。**十文字さんの4つの問い（詰まり・発売の見通し・新商品の売上・パイプライン）のうち、画面にあるのは詰まりだけ**。発売の見通しは「4週以内の発売予定」の表だけで、本番では案件20件すべてに発売予定日が無いため常に「ありません」。新商品の売上とパイプラインは無い
3. 「月次で見るもの」のボタン行（月次レポートを見る）が、グリッドより**前**に置かれている（`b.appendChild(btnRow(...))` が `g2` の追加より先）。カード群の上に、関係のなさそうなボタンが浮く
4. 「コンセプト在庫月数 3.5」が大きな数字だけ。下限（`floor` 3.0）・月の目標本数（4.0）・元の件数（14件）は API にあるのに、関係が見えない
5. 「要注意」は件数だけで、母数が無い（期限なし 75 件が多いのか少ないのか分からない）
6. 1-5 の見出しの逆転（h2 24px ＞ h1 20px）

- **見づらい所**: A節の表が11行の縦の「項目／値」で、空欄が多い（本番の例: 分類・開発タイプ・発売予定日・機会・担当・工数ポイントが空）。ゲートは札が並ぶだけで、どこまで来たか一目で分からない。たたんだ節の題（summary）には進み具合が出ず、**開かないと「0 / 5 入力済」が見えない**
- **足す視覚要素**:
  - A節の上に**段の帯** G0〜G6（`d.gates[].state / glyph / word / required_n / missing`）。いまの位置（`d.next_gate`）に「いまここ・欠 n 件」の語。対象外は斜線の升目＋「対象外」

  - タスクの節: **期間の帯** `timeline`（`tasks[].start_on / due_on / status`、目安は `plan_start / plan_due` を白抜きの帯で重ねる）。今日の線は `d` に `today` を足して渡す。行の名前は `seq` と `title`。**完了日が今日より後の行（移行の誤りと推測）は帯を描かず「完了日に疑い」と語で**

- **並べ方**: 段の帯 → A（ヘッダ。空の項目は「未入力: 分類・開発タイプ・発売予定日・担当」の1行にまとめ、埋まっている項目だけ表に）→ B いま欠けているもの → 目次（各節に升目）→ 各節
